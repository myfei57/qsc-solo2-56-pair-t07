# 应急演练子系统（psdline.drill）

值班员每年都要演练，但只能等设备空下来才能真操作，早高峰根本练不了。这个子系统
让人**用真实站台、列车、门区数据在真代码上推演应急处置，而一条现场动作都不许真的
发出去**；演练结束后，每一步的结果、判断依据、用时和得分都能复盘，且历史不可篡改。

演练、门控、审计、存储放在同一个包里一起设计，核心目标只有一条边界：

> **演练世界与现场世界物理隔离；演练痕迹永远不混进现场事实。**

---

## 1. 两种数据模式（取舍与适用）

系统**两种模式都支持**，价值不同，按演练目的选：

| | `shadow`（实时分叉） | `replay`（快照重放） |
|---|---|---|
| 数据 | 创建瞬间**复制当前实时现场数据**后分叉 | 从一张**故障时刻快照**重放 |
| 时间 | 演练时钟可按真实墙钟 1:1（或加速）驱动 | 手动 `tick` 步进，完全确定性 |
| 价值 | 贴近此刻真实工况、早高峰随时可演；边演边可只读对照"现场此刻" | 同一故障可反复演练、横向比较不同值班员；复盘逐字节可复现 |
| 副作用 | 只在创建时读一次现场（复制），之后与现场再无写关系；演练期间另有只读采样 | 全程不碰现场存储 |

推荐：**日常练手/早高峰随时推演用 shadow；考核、复盘、新员工横向对比用 replay。**
一次 shadow 创建时拍下的实时快照，天然就能作为之后 replay 的素材（故障时刻快照）。

两种模式跑的是**同一份确定性引擎**，差别只在数据来源和谁来敲钟。

### 演练期间能不能切回实作？

**不能。** 这是明确的安全取舍：演练进行中，该会话不提供任何"切到真实现场执行"的
通道。唯一的出口是**双人破玻（break-glass）**——值班员与第二名复核人（不能同人）
共同确认，会话不可逆地转为 `abandoned`，历史照样冻结保全。破玻退的是演练工作站，
而现场平台从设计上就不被演练服务调用，因此破玻不影响现场任何状态。

## 2. 门控：为什么现场动作一条都出不去

纵深防御，四层，任意一层都足以挡住越界，且全部 fail-closed（状态不明即拒绝）：

1. **物理隔离（首要）**：演练平台的存储是快照**分叉出来的独立目录副本**，不是软链接、
   不共享目录。演练在副本上推演，默认根本没有通往现场的写路径。启动时还会自检
   分叉目录与现场目录既不相同也不嵌套（`assert_isolated_fork`）。
2. **存储边界（`BoundedStore`）**：演练平台持有的每个写操作都被限定在分叉目录根内，
   路径越界直接抛 `GuardRejected`。即使上层逻辑错误地构造了现场路径，也会在这里被挡下。
3. **出口哨兵（`EgressGuard`）**：每个处置动作执行前后各过一道检查——边界必须 armed、
   会话必须与边界登记一致、目标必须落在本会话分叉目录内。未武装默认拒绝一切。
4. **现场只读视图（`ReadOnlyLiveView`）**：shadow 采样现场时拿到的视图只有读方法，
   类型层面就没有写入口。

演练跑的是与现场**同一套 `Platform` 代码**（同样的联锁、配额、对位公差、间隙判定），
因此"动作被现场拒绝"这种结果在演练里也是真实发生的——演练不是简化模拟器。

---

## 3. 审计：哈希链 WORM，与现场审计完全分离

每个会话一条 `events.jsonl`，每个处置动作记**两条**事件：

- `request`：值班员意图（动作、参数、人），**先 fsync 落盘**；
- `result`：在分叉平台真执行后的结果 + 执行后的世界内容指纹。

每条记录带 `seq / sim_time / kind / actor / payload / prev_hash / hash`，其中

```
hash = sha256( 规范序列化({seq, sim_time, kind, actor, payload}) ‖ 前一条 hash )
```

墙上时钟 `wall_at` 只作注释、**刻意不进哈希**，保证同一份事件在任何机器/时间重放都
逐字节一致。改一个字段、删一行、调换顺序，从该行起链全部断裂，打开日志即 fail-fast。

- 终态封存后文件降为只读（0o444），是哈希之外的第二道防线；
- 现场审计（`audit-*.jsonl`）与演练哈希链是**两套独立文件**，演练动作永不写现场审计；
- 提示（hint）请求本身也进链——"看过答案"留痕，但提示不替值班员做决定。

## 4. 存储布局

```
<storage_root>/
  live/                         # 现场当前态（JsonStore）与现场审计 JSONL
  drill/                        # 演练根，与现场同级、互不嵌套
    sessions.json               # 会话名册（原子替换；只是检索摘要，可重建）
    snapshots/<hash12>/bundle.json   # 内容寻址、只读、同内容去重的快照
    sessions/<DR-id>/
      meta.json                 # 会话权威元数据/状态机
      events.jsonl              # 哈希链事件日志（封存后只读）
      fork/                     # 分叉世界副本（演练平台的存储根）
      report.json               # 封存时的只读复盘报告
      DR-id.lock                # 跨进程会话文件锁
```

- 快照是**内容寻址**：`sha256(规范化(全部文档))`。同状态拍多次指纹相同、自动去重；
  一个字节变化就换目录。现场审计流水只作为快照里的只读 `audit_tail` 观察，**不进入分叉**。
- 名册损坏可从各会话目录的权威 `meta.json` 一键重建。

## 5. 会话状态机

```
pending ──► armed ──► running ◄──► suspended
   │          │         │  ╲          │
   └──────────┴─────────┴──► abandoned (破玻/异常，终态，不可逆)
                         └──► sealed    (正常封存，终态，不可逆)
```

只有 `running` 接受处置动作；`suspended` 只接受恢复；终态冻结。任何白名单外的跳转
一律拒绝。同一时刻只有一个执行体能处置某会话（进程内 RLock + 跨进程 `fcntl` 锁），
第二个人/进程拿到的是"会话被占用"，不会写出交错的事件链。**多场演练并发互不干扰**：
各有独立目录、时钟、分叉平台、事件链、锁。

---

## 6. 崩溃安全与部分失败恢复

处置动作的落盘顺序是 **意图先 fsync → 执行 → 结果 fsync**。据此处理崩溃：

- 服务重启跑 `recover_all()`：
  - `running` 且链完整 → 转 `suspended` 并标记 `recovered`，**等值班员显式 resume**，
    不自动继续（避免驱动时间凭空流逝）；
  - 最后一个动作"有 request 无 result"→ 标记为 `in_flight`，**绝不自动重发**
    （现场语义下它可能已经生效，重发可能二次动作）；
  - `armed`（还没注入故障）→ 保持上膛，可重新开始；
  - `pending`（连分叉都没建成）→ fail-closed 放弃为 `abandoned`，杜绝半初始化复活；
- 掉电瞬间末行写了一半（非法 JSON 的撕裂行）：打开时只截掉这一条从未 fsync 完整的末行，
  已确认的完整记录一条不丢；
- 哈希断裂不是撕裂，绝不静默处理，直接拒绝打开。

`tools/crash_worker.py` + `tools/drill_demo.py` 用真实子进程 `os._exit(9)`（kill -9
语义）验证了这条契约。

## 7. 评分：每一步都能看到判断依据

剧本声明标准步骤（动作、时限、是否关键、权重、谓词、依据）。谓词检查的是**结果是否
满足处置意图**，而不是动作名字——例如"清故障"必须是对那樘故障门、且返回 `ok`，给
别的门清就算动作名对也判错。判定口径：

- `ok` 时限内做对；`late` 做对但超时（折半得分）；`wrong` 同名动作但对象/结果错；
  `missed` 到结束没做对；
- 关键步漏做 → 直接不合格；**间隙未确认安全就尝试发车**等危险动作单独记关键违规，
  即使后来补做成功也不合格；
- 多做的非剧本动作记录但不扣分。

封存时算一次写进只读报告；深度复核时从事件链**从零重放**再算一次，两次不一致即
判定报告/历史被动过。

---

## 8. 深度复核（封存后）

`verify_session` 对终态会话做四件事：

1. 重算整条哈希链；
2. 用一张全新分叉、从 `setup → 注入 → tick → 每个动作` 重新执行，把每个动作的
   **规范化结果**与当初落盘结果逐字节比对（剥离 op_id/audit_id 等非确定标识）；
3. 比较重放终态世界指纹与封存时指纹（确定性，排除实例名等身份文档）；
4. 用重放事件重算评分，与报告评分核对。

四者全过才算复核通过。

## 9. 使用

### 命令行

```bash
make run-drill                       # 控制台同时挂现场 + 演练
python -m psdline --storage-root var/state drill scenarios
python -m psdline ... drill start --scenario psd_fault --mode shadow --actor 张三
python -m psdline ... drill act  <SID> --action sweep --json '{"station_id":"ST1"}'
python -m psdline ... drill tick <SID> --dt 1          # replay 手动步进
python -m psdline ... drill hint <SID>                 # 下一步提示（会留痕）
python -m psdline ... drill seal <SID>                 # 封存出成绩单
python -m psdline ... drill verify <SID>               # 深度复核
python -m psdline ... drill break-glass <SID> --actor 张三 --confirm-by 李四 --reason ...
python -m psdline ... drill timeline <SID>             # 逐步事件链
python -m psdline ... drill report <SID>               # 只读复盘报告
```

> 命令行每次调用都是新进程（等价于一次潜在重启），因此在二次操作前需要显式
> `resume`——这是 fail-closed 的设计，而不是麻烦。

### HTTP（前缀 `/api/drill`，独立错误映射）

`GET /api/drill/scenarios`、`GET /api/drill/snapshots`、`GET/POST /api/drill/sessions`、
`POST .../{id}/prepare|start|act|tick|hint|suspend|resume|seal|break-glass|verify`、
`GET .../{id}/world|timeline|report`。状态码：会话冲突 409、不存在 404、出口拒绝 403、
历史篡改 422、参数错误 400。现场 `/api/*` 与演练 `/api/drill/*` 互不影响。

### 自演示与验证

```bash
make drill-demo     # 两种模式 + 跨进程 kill -9 崩溃恢复 + 隔离逐文档比对 + 篡改检测
make test           # pytest（CI）
make test-offline   # 无 pytest 时的零依赖兜底
```

内置三个基于真实对象的剧本：`psd_fault`（站台门故障）、`gap_alarm`（发车前间隙可疑）、
`stale_position`（位置报文失准）。
